# Plan F3 — Importar rescate + admin contra API (159A-2)

## Objetivo
Cargar los 5 inmuebles + 48 originales + 34 mejoradas + copy en Postgres, y que el admin
de INMOBILIARIA lea/escriba contra la API Rust (adiós localStorage/IndexedDB como fuente).

## Alcance
- Backend (MN-Inmobiliaria): migración `copy_*`, `POST /api/admin/fotos/upload` (bytes crudos,
  sin deps nuevas), `GET /uploads/*` estático, `UPLOAD_DIR`, script `scripts/importar-rescate.mjs`.
- Admin (INMOBILIARIA): cliente API + login, `repositorio-inmuebles` contra REST (misma firma
  que usa `useInmuebles`), subida de fotos al endpoint, mejora/copy-IA sin cambios de fondo
  (leen por URL vía fetch→dataURL donde haga falta).
- Importados con `publicado=false` (borradores a revisar; el owner publica).

## No alcance
- Web pública (F4, espera diseño usuario). Mejora-IA en servidor. Deploy (F5).

## Fases
1. **Backend copy+uploads** — migración 00003, modelo/servicio/handlers, upload bytes +
   validación magic-bytes/extensión (jpg/png/webp, tope 10 MB), estático `/uploads`,
   `UPLOAD_DIR` en `.env.example`+`.env`. DoD: `fmt+check+clippy+test` PASS.
2. **Import** — script node (register-or-login, mapea uuid viejo→nuevo, crea con copy,
   sube originales por índice + mejoradas `lista` matcheadas por contenido exacto).
   DoD: 5 inmuebles, 48 originales, 34 mejoradas, 2 copy; pública sigue en 0.
3. **Admin→API** — `src/data/api.ts`, login (`VITE_API_URL`, token en sessionStorage),
   repositorio contra REST, fotos como URL, `tsc -b && vite build` PASS + CRUD real en navegador.
4. **Cierre** — completadas en ambos repos, commits separados (`159A-2`), roadmap releído.

## Gotchas 2026-09-15 (fases 1-2)
- axum 0.7.9 usa sintaxis de rutas `:param` (como el resto del template); `{param}` se
  registra como literal y devuelve 404 vacío, y `{*ruta}` hace panic al arrancar. Ruta
  final: `/uploads/:inmueble/:archivo` (dos segmentos exactos, sin wildcard).
- El runner mata `Start-Process` con redirección (proceso background imposible): la
  verificación del import se hace con test de integración que levanta la app in-process
  en puerto efímero (`127.0.0.1:0`), sin procesos sueltos.
- Alguna mejorada declara en la cabecera `data:image/...` un formato distinto a sus bytes;
  la extensión se deduce por magic-bytes (servidor y test exigen coherencia).
- Un `glory-backend` ajeno (`C:\tmp\glory-target\debug\...`) ocupaba el puerto 3100:
  de ahí el puerto efímero en el test.
